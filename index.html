FacePass – Face Recognition
GitHub Repository →

Overview

FacePass is a hybrid real-time facial recognition system. The browser handles detection and embedding extraction using face-api.js, while the backend performs identity matching via a lightweight Flask service. This allows recognition without GPU hardware on the client.

Motivation

Traditional face recognition pipelines require GPU acceleration or native frameworks. FacePass explores whether modern browser technologies such as WebRTC + WebGL can support real-time recognition on standard consumer devices for educational and lightweight applications.

Tech Stack

face-api.js TensorFlow.js WebRTC Flask NumPy Python HTML/CSS

Architecture

  • Client: webcam capture via WebRTC
  • Detection: face-api.js bounding box estimation
  • Embedding: 128-D face embedding extraction
  • Transport: embeddings sent to backend over JSON
  • Backend: Euclidean similarity computation against stored embeddings
  • Output: identity label + confidence score returned to client

Embedding Details

  • Representation: 128-D vector
  • Metric: L2 Euclidean distance
  • Threshold: configurable (default = 0.6)
  • Lower distance → stronger match

Performance

  • Runs at ~15-30 FPS depending on device
  • Operates fully on CPU
  • Stable under common indoor lighting
  • Best accuracy on frontal captures

Limitations

  • Reduced accuracy under occlusion (masks, hats)
  • Low light affects detection confidence
  • Mobile devices vary in real-time performance
  • Single-face focus (multi-face tracking planned)

Future Improvements

  • Add multi-face tracking
  • Support cosine similarity + classifier-based matching
  • User enrollment interface
  • Adaptive threshold calibration
  • WebGPU acceleration exploration

Dataset Notes

Embeddings were generated using live webcam captures. More samples per subject across lighting conditions and angles improve robustness and identity separation in embedding space.

Privacy Considerations

Raw video frames remain local to the browser. Only embeddings (numerical vectors) are transmitted to the backend. No cloud inference or 3rd-party APIs are used, reducing privacy risk.
